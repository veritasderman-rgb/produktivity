In discussions about home agents, the Mac mini gets recommended over and over. It's a good machine, and [we have a part about it](/agenti/mac-mini-jako-domaci-ai-server). But plenty of people buy one for something that can be handled by the box that has been sitting in a cupboard next to their router for five years.

## Why a NAS is enough

It rests on one distinction: **an agent is not a model.**

The model is the part that thinks. It needs a lot of memory and a fast chip, which is why expensive machines get bought for it. The agent is the part that drives the model: it remembers what you told it, keeps the schedule, reads messages from Telegram and calls tools. That takes very little.

Hermes Agent states one core and 1 GB of memory as the minimum, and recommends two cores and 2–4 GB. That's an ordinary Synology from the Plus series. The model, meanwhile, runs elsewhere — at OpenAI, Anthropic or via [OpenRouter](/agenti/openrouter-jeden-klic-zaloha) — and the NAS merely sends it queries.

| | The Synology you have | Mac mini |
|---|---|---|
| Purchase price | zero | tens of thousands of crowns |
| Agent with a model in the cloud | yes | yes |
| Model right at home | no | yes, depending on memory |
| Runs non-stop | already does | you have to set it up |
| Data the agent is close to | everything on the NAS | only what you give it |

Read the last row twice. It's an advantage and a risk at the same time, and we'll come back to it.

**So you don't have to have a Mac mini, but you can.** It makes sense when you want the text never to leave the house at all. The agent can then stay on the NAS and simply ask the Mac mini — that's the division of labour from [setup 2](/agenti/sestava-tichy-server-nocni-smena).

## What to check before you start

- **Container Manager.** Open Package Center in DSM and search for it. If it isn't there, your model can't run containers and this setup isn't for you.
- **Processor.** Models with Intel or AMD are trouble-free. For low-power models with an ARM processor, check that an official image exists for your architecture; sources disagree on this.
- **Memory.** With 2 GB it will be a struggle, with 4 GB comfortable. On the Plus series, memory can usually be added.

## Installation in half an hour

A detailed walkthrough, including the terminal for beginners, is in [setup 4](/agenti/sestava-pamet-nad-zpravami-beeper-hermes). Here is just the skeleton for a single container:

```yaml
services:
  hermes:
    image: nousresearch/hermes-agent:latest
    container_name: hermes
    restart: unless-stopped
    command: gateway run
    volumes:
      - /volume1/docker/hermes:/opt/data
    mem_limit: 4g
```

Paste it into a new project in Container Manager. Then run the setup wizard once over SSH:

```bash
sudo docker run -it --rm \
  -v /volume1/docker/hermes:/opt/data \
  nousresearch/hermes-agent setup
```

The wizard asks about the model and about the channel the agent should use to talk to you. For Telegram you need a bot token and your numeric ID; the procedure is in the part [Telegram as a control panel](/agenti/telegram-jako-ovladaci-panel). Notice what's missing from the skeleton: **a `ports` line**. The agent polls Telegram itself; nobody connects to it from outside.

Do two things before you give it its first task:

1. **Give it its own folder, not the whole NAS.** The container sees only what you mount into it. If you want it to sort scans, mount the folder with the scans. Not `/volume1`.
2. **Set a spending cap** with the model provider. An agent with a schedule spends money even while you sleep.

## Where the line is

The list is ordered deliberately. In the first twenty, the agent sees nothing of yours and the worst that can happen is a bad summary. From number 61 onwards it reads things written by strangers and at the same time sees your data — and that's the combination covered in the part on the [lethal trifecta](/agenti/smrtici-trojice-agentu).

For a NAS, four rules follow from that:

- **The agent proposes, you send and delete.** An email draft yes, sending no. A list for archiving yes, deleting no.
- **Back it up.** What to save and where, so the agent can be restored, is dealt with in the part on [backups](/agenti/zalohy-agenta-obnova-za-deset-minut).
- **The mounted folder is the boundary.** What the container can't see, it can neither read nor send out. That's why you never mount the whole volume.
- **Leave command approval switched on.** For scheduled tasks, Hermes has dangerous commands disabled by default. Leave it that way.

And one extra rule that applies only here: **the NAS is where you keep your backups.** An agent with write access to them is the one thing capable of ruining both the data and its backup at once. Don't mount the backup folder for it at all.

How to lock down a NAS with an agent against access from outside is shown in the part [Synology from outside](/agenti/synology-bezpecny-pristup-zvenci).

After the first quarter, an [audit](/agenti/tri-mesice-s-agentem-co-vypnout) will come in handy to show which of those hundred tasks you actually read, along with the part on [what a month with an agent costs](/agenti/co-stoji-mesic-s-agentem).

## When not to build it

- **You have no recurring tasks.** If you ask an agent something once a week, a phone app is enough.
- **The NAS is at its limit.** If it already struggles to keep up when playing video, another container won't help it.
- **You want the model at home.** Then it really is a job for a Mac mini or a computer with a graphics card.

---

The sensible approach is boring: install it, give it three tasks from the first twenty and watch for a week whether you read them. If you do, add more. If not, none of those hundred items will help you — and you found that out for free, on a machine you already had.
