Most people use image generators exactly one way: open the website, type a prompt, wait, download, resize, upload. For one image, that's fun. By the twentieth, it's work — and it shows, because each one came out in a different mood and a different style. But the same service almost always has an API too. And that opens up a different world: **write the style prompt once, and from then on an image is just one command.** Not half an hour in an editor.

## A typical scenario

Klára, a freelance graphic designer, runs a blog for a finance client. Every article needs a header illustration. Until now that meant: come up with a motif, write a prompt, generate four variants, pick one, regenerate, open an editor, crop to the right aspect ratio, export, compress, rename, upload. Thirty to forty minutes per image. And after six months, the blog looked visually fractured — older illustrations had different colors than newer ones, because the model and her own taste had both shifted in the meantime.

Now Klára has a style brief saved in a file and a short script. She writes one sentence about the motif, runs the command, and a minute later has a finished image at the right size, in WebP format, speaking the same visual language as all eighty before it. The work on an illustration has shrunk down to thinking up the motif.

That's how the illustrations on this site are made, too. There's a single style prompt — a black-and-white line drawing with a single red accent — a script that [Claude Code](/tipy/ai-skripty-pro-nevyvojare) wrote, and a connection to Google's image API. The output gets automatically compressed to WebP and saved under the right filename. A new article means one command, not half an hour in a graphics editor.

## How to do it

1. **Define the style first, not the image.** Write a paragraph describing the technique (line drawing, watercolor, flat vector illustration), the color palette (even just two colors), the mood, the background, and what to avoid. That paragraph is the core of the whole thing — the images change, the style stays.
2. **Try the style by hand first.** Before writing any script, run five different motifs through a regular web-based generator using the same style paragraph. If the results visually hold together, you're set. If not, keep refining the description — this is the cheapest step to iterate on.
3. **Have a script written for you.** You don't need to know how to code. Tell your AI assistant: “write me a script that takes my style prompt, appends a motif description from an argument, calls the image API, saves the result, and converts it to WebP at 1200px wide.” You'll get working code plus instructions on what to install.
4. **Create an account and an API key.** With services like Google AI Studio or OpenAI, generating a key takes a few clicks in your account settings. Put the key in an environment variable, not in the script.
5. **Add one last step: compression and naming.** An uncompressed generator output is routinely several megabytes. Automatic conversion to WebP and sensible naming based on the article save more work than you'd expect.
6. **Generate several variants at once.** The script can produce three images instead of one, and you pick. Still faster than one round of manual clicking.

## The best tools

- **Google's image API (Gemini)** — good quality, a simple interface, and you can get a key from [Google AI Studio](https://aistudio.google.com) in a minute.
- **Claude Code** — writes the script, tests it, and runs it right away; works even for someone who can't read code.
- **Sharp or ImageMagick** — libraries for automatic cropping and WebP conversion; add to the script in a single line.
- **Your own style-prompt file** — the most important “tool” on this whole list, even though it's just a text file.

## What you get out of it

- **Time:** from thirty minutes per image down to one or two. For a site with dozens of articles, that's tens of hours a year.
- **Consistency:** every illustration comes from the same brief, so they hold together even a year later.
- **Peace of mind:** the most annoying part disappears — manual cropping, compressing, and renaming files.
- **Quality:** because generating is cheap, you can afford to throw out a bad image and make a new one.

## Pro tip

An API key is a password, even though it doesn't look like one. Keep it in an environment variable or a file that never goes into a public repository — never directly in the text of a script you send or publish anywhere. A leaked key can be turned into someone else's money within hours. And a second rule: **you trigger the generation, you approve the publication.** Have the script save images to a folder, not straight to the site — look at every image before it goes live. Generators can, every now and then, produce nonsense, distorted text, or a motif that simply doesn't belong in a finance article.
