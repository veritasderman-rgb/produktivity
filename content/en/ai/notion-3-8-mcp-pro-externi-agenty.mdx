**What happened:** On October 13, 2026, Notion released version 3.8, subtitled "Context for your agents". The headline change is that **any compatible AI agent** can now connect to Notion through MCP (Model Context Protocol), read your workspace context, and update docs and task databases. According to the release notes, admins can see who connected which AI tool and when it was last used, and can **revoke one person's access**. However, Notion's help page reserves MCP governance at workspace level (allowing only approved apps, an overview of connected tools) for **Enterprise admins**, and says detailed per-user visibility is not yet available. The release also adds version history for pages and databases (highlighted edits, database change details, attribution and one-click restore), per-column permissions in databases, and a Skills API that syncs skills from Notion to tools such as ChatGPT and Claude. Notion Agent and custom agents also gained 150+ tool connections (HubSpot, Stripe and Cloudflare, for example). Notion does not state plan availability for most of these items, so check it for your own workspace.

**What it means for you:** Notion shifts from a place where you store data to a shared memory for all your AI tools. You no longer paste context into a chat every time — the agent reads it itself. In practice:

- **Planning from one source** — in Claude you write "based on the project page in Notion, prepare the agenda for Thursday's meeting and add three follow-up tasks". The agent reads the page, proposes changes and writes them.
- **One set of procedures** — a skill your team uses in Notion Agent (say, "how we write the weekly report") can sync to other tools, so you don't write the procedure twice.
- **Control over what happened** — with version history and column permissions you can see what an agent changed and roll it back.

**How to start:**

1. In Notion, open the connection settings and link your AI assistant following the [Notion MCP help page](https://www.notion.com/help/notion-mcp).
2. Keep in mind that MCP tools act with **your full Notion permissions** and can reach everything you can. Notion itself won't limit an agent to a single page — you can narrow access with tighter permissions on the account you connect, or by requiring confirmation of each action in the AI tool. Give the first task as read-only — a project status summary, for example.
3. Once you're comfortable, allow writing and try a small edit, such as adding a due date to a task.
4. If you manage an Enterprise workspace, go through the list of connected tools and block the ones that aren't approved.

**What to watch out for:** An agent with write access can change your team's documents and acts with your full permissions. Enable writing and action confirmations in the AI tool deliberately, and use version history to review changes. Connect only tools approved by your company to workspaces holding personal data or confidential contracts. The same principle applies as everywhere: AI proposes, a human approves the changes — especially in documents other people read.
